Problem

Every mainstream downloader asks you to trust it quietly.

Closed-source download managers bundle ad SDKs, phone-home analytics, and — increasingly — YouTube-ripping engines that exist purely to strip DRM at scale. You can't audit what you can't see, and "free" download apps are rarely free of a business model somewhere underneath.

Solution

Full source. Local-only checks. One mode that can't leak.

YFDW is a direct-URL downloader with a browser attached, not a media-extraction tool with a browser bolted on. Every security claim — the kill switch, the malware hash check, the encrypted logs — runs entirely on-device and is in the repo for you to read.

Features

What's actually in the build

Six shipped systems, and — placed here deliberately rather than hidden — the one capability that was scoped out on purpose.

Brave-style browser

Full WebView with search, live page rendering, and automatic scanning for downloadable media as you browse.

32-chunk parallel downloads

Splits large files across HTTP Range requests with auto-resume — a 3–5x speedup over single-threaded downloading.

Embedded Tor

Guardian Project's tor-android, bootstrapped with zero external configuration when Privacy & Anonymity mode is on.

Kill switch

Continuously checks for an active VPN or Tor connection in Privacy mode. Neither present → the app exits, full stop.

Local malware-hash check

Streaming SHA-256 verified against a local blocklist before any file is finalized. No third-party API calls, nothing leaves the device.

SQLCipher logs

Download history encrypted at rest with AES-256-GCM, key backed by Android Keystore.

Pending

Universal Media Extraction Engine

NewPipe-style stream ripping from YouTube and streaming platforms.

Security

Two modes. One of them can't fail quietly.

Every claim below is enforced in code you can read, not a policy you have to take on faith.

PropertyPrivacy & AnonymityStandard
Network requirementVPN or embedded Tor requiredNone — any network
Kill switchArmed — auto-exits if neither detectedDisarmed
Tor serviceStarted on demandNever started
Encryption / scoped storage / hash checkOnOn

Switching modes re-checks immediately

Choosing Privacy & Anonymity mode isn't a settings flag that takes effect later — it triggers an immediate connection check. If neither VPN nor Tor is active at that instant, the kill switch fires right away and the app exits, preventing an accidental IP leak in the gap between switching modes and actually connecting.

What "local-only" actually means here

The malware check hashes each file with streaming SHA-256 as it writes, then compares against a JSON blocklist that ships in the app — no network call, no third party sees your download history. It's a real trade-off: it catches previously-seen malware, not zero-days. That's stated plainly, not implied to be more than it is.

Architecture

Security layer, isolated by design

Security: NetworkVpnObserver → detects active VPN transport TorManager → bootstraps embedded Tor, SOCKS proxy SecurityGate → monitors state, fires kill switch if Insecure Downloads: DownloadChunkPlanner → splits files into 1–32 chunks ChunkDownloader → HTTP Range headers, parallel fetch DownloadEngine → orchestrates probe→plan→fetch→merge→hash→check Local integrity: StreamingHasher → SHA-256 while writing, no second pass MalwareSignatureChecker → local JSON blocklist, no external API calls

FAQ

Before you ask

Can it download from YouTube?

No, and that's not a missing feature waiting on a future release.

Does Standard mode collect anything?

No. Standard mode disarms the kill switch and skips Tor, but encryption, scoped storage, and the local hash check stay on in both modes. There is no analytics path in either.

What happens to a file that's already downloading if the kill switch fires?

The app exits. In-flight chunks stop; nothing further is transmitted. This is the known trade-off of a hard kill switch — it favors never leaking over graceful continuation.
